# Releasing to the `trainingloadai` npm organization

The public package name is `@trainingloadai/garmin-personal-api-mcp`. The `@trainingloadai/`
prefix is what publishes it under the npm organization rather than a personal account. The npm
account performing the first publish must be a member of `trainingloadai` with write permission.

## One-time bootstrap

The first version must exist on npm before npm can attach a Trusted Publisher to it.

1. Sign in with an npm account that belongs to the organization and has 2FA enabled:

   ```bash
   npm login
   npm whoami
   npm org ls trainingloadai
   ```

2. Run the complete release checks from the repository root:

   ```bash
   pnpm install --frozen-lockfile
   pnpm check
   pnpm test:coverage
   pnpm smoke:pack
   ```

3. Inspect the tarball contents without publishing:

   ```bash
   pnpm --dir packages/mcp-server pack --dry-run
   ```

4. From `packages/mcp-server`, create the public organization package. The explicit
   `--provenance=false` is only for this local bootstrap; provenance is generated by GitHub Actions
   on later releases:

   ```bash
   npm publish --access public --provenance=false
   ```

   This is the only command in this guide that changes the public npm registry. It may require a
   2FA code, depending on the npm account’s settings.

5. On npmjs.com, open the new package’s **Settings → Trusted Publisher** and add GitHub Actions:

   - GitHub organization or user: `trainingload-ai`
   - Repository: `garmin-personal-api-mcp`
   - Workflow filename: `release.yml`
   - Environment: `npm`
   - Allowed action: direct `npm publish`

   Also create or protect the matching `npm` environment in the GitHub repository. npm requires
   the first successful trusted publish within two days after creating the relationship.

## Later releases

Update the package version and changelog, run the checks, and create a matching `vX.Y.Z` tag. The
release workflow verifies that the tag matches `packages/mcp-server/package.json`, publishes with
OIDC Trusted Publishing, and creates a GitHub release. It does not use a long-lived npm token.

Do not publish from a dirty or unreviewed tree. Never commit npm access tokens or put them in the
package, `.npmrc`, GitHub logs, or release artifacts.
